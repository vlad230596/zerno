## 4. Отложено осознанно

Не баги. Записано, чтобы не переоткрывать спор.

| Что | Почему отложено |
|---|---|
| Удаление правила не откатывает уже проставленные категории | Движок просто перестаёт следить. Осознанное поведение |
| Переименование служебного счёта `🤖 [Zerro Data]` | Поиск скрытых данных идёт по полю `type` внутри JSON по всем напоминаниям, а не по счёту. Переименование данные не изолирует, зато создаёт второй служебный счёт и вытаскивает старый в списки UI |
| `og:url` и `og:image` в `index.html` | Ждут домена |
| Сервер, хранящий токен ZenMoney | Не рассматриваем. Приложение будит сервер, ничего не знающий о данных: `zerno-push` шлёт пустой пуш, текст считает воркер |

## 5. Открытые вопросы, на которые нет ответа

Из [notifications.md](./features/notifications.md) и
[split-bill.md](./features/split-bill.md) — решения, которые нужно принять до
кода, а не после.

- Одно вечернее уведомление на всё или отдельное на каждый кейс?
- Где хранить разметку счетов — и не станет ли её ведение вручную той самой
  работой, ради избавления от которой всё затевалось?
- «Уже потеряно за все предыдущие дни» — с какого момента считать и не
  превратится ли число в фон?
- Что делать, если уведомление показано, а перевод не сделан: повторять?
- Насколько надёжен вечерний фоновый запуск на телефоне, чтобы строить на нём
  сценарии с дедлайном «сегодня»?
- Что делать, если человек вернул не всю сумму долга или больше? (Вероятно,
  достаточно оставить долг ненулевым.)
- Нужна ли отдельная страница «Кто мне должен» или хватит `DebtorList`?

## Что проверить на реальных данных

Перенесено из [known-issues.md](./known-issues.md) — открытых дефектов там нет,
но эти проверки не выполнены.

- **Страница правил:** сколько исключений накопилось. Большое число — след
  старого храповика, их можно вернуть под правила.
- **«Баланс»:** полоска «Без категории по месяцам». Месяц, пройденный руками,
  должен оставаться нулевым.
- **Вкладка операций с пустым фильтром:** «Итого» за всю историю должно
  совпадать с суммарным остатком по счетам.
- **Консоль после первой синхронизации:** `Hidden store ... is damaged` означает,
  что комментарий напоминания не дочитывается. Само напоминание при этом цело.

# Что изменено относительно Zerro

Zerno — личный форк [Zerro](https://github.com/ardov/zerro) (GPL-2.0, © ardov).
Точка ответвления — коммит `be47283a` («Merge pull request #207 from
osipxd/fix-month-list-start»).

Этот документ описывает первую порцию изменений: то, с чего начинается история
форка. Дальше он ведётся как обычный список расхождений с апстримом — при
`git merge upstream/master` полезно свериться, не задел ли апстрим те же места.

Объём: **19 изменённых файлов** (+695 / −438) и **30 новых** (~3600 строк в `src`).

## 1. Поиск операций как язык запросов

Самое крупное изменение. Прежние `TopBar/Filter.tsx` и `TopBar/FilterDrawer.tsx`
(311 строк формы с полями) **удалены**, вместо них — строка поиска, которая
разбирает запрос на типизированные токены.

**[`4-features/transactionSearch`](../src/4-features/transactionSearch)**

| Файл | Что делает |
|---|---|
| `parseQuery.ts` | Токенайзер. Понимает `#категорию`, магазин, счёт, сумму (`>1000`, `100..500`), дату, тип (`доход`/`расход`/`перевод`/`долг`), id операции, флаги `new`/`deleted` и свободный текст. Каждый токен помнит своё точное место в строке (`raw`/`start`/`end`) — на этом строятся чипсы поверх инпута и правка запроса по клику |
| `matchers.ts` | Сопоставление слов из запроса со словарями категорий, счетов и магазинов. Отдельно — алиасы «без категории»: `#нет`, `#без`, `#none`, … |
| `compileQuery.ts` | Токены → `TrCondition`, то есть в существующий механизм фильтрации проекта, а не в свой параллельный. Плюс `makeNoTransfersCondition` для настройки «игнорировать переводы» |
| `useTrSearch.ts` | Хук поиска для списка операций |
| `useSuggestions.ts` | Автодополнение. Служебный счёт `🤖 [Zerro Data]` из подсказок исключён |

**UI:** `TopBar/SearchBar.tsx` (строка поиска с автодополнением),
`TopBar/QueryChip.tsx` (визуализация токенов), `TopBar/QueryHelp.tsx`
(шпаргалка по синтаксису, примеры кликабельны и вставляются в запрос).

**Тесты:** `parseQuery.test.ts`, `compileQuery.test.ts` — 255 строк.

## 2. Правила категоризации

Подробное описание с обоснованием решений — в
[`docs/features/auto-categorization.md`](./features/auto-categorization.md).
Коротко: операция размечается правилом автоматически, ручная правка категории
у конкретной операции перебивает правило навсегда.

- **[`5-entities/rule`](../src/5-entities/rule)** — модель `TRule` и движок
  `runAllRules()`. Условие правила — тот же `TrCondition`, что у поиска;
  отдельного языка условий нет. Порядок правил в массиве = приоритет.
- **[`4-features/transactionRules`](../src/4-features/transactionRules)** —
  `RuleModal` с живым превью (сколько операций за всю историю попадёт под
  правило и какие именно), `describeRule` для человекочитаемого описания.
- **[`2-pages/Rules`](../src/2-pages/Rules)** — страница `/rules` со списком
  правил и перетаскиванием приоритета через `@dnd-kit`.
- Правила и состояние разметки лежат в скрытом хранилище: два новых значения
  `HiddenDataType.Rules` и `HiddenDataType.RuleState`
  ([`hidden-store/types.ts`](../src/5-entities/shared/hidden-store/types.ts)).
- `runAllRules()` вызывается сразу после каждой синхронизации
  ([`4-features/sync.ts`](../src/4-features/sync.ts)), чтобы свежие операции не
  успевали показаться с чужой категорией.
- **Тесты:** `condition.test.ts` — 144 строки.

## 3. Список операций

- **`FlatList.tsx`** — виртуализированный список без разделителей по датам.
  Нужен, когда сортировка не по дате и заголовки дат теряют смысл.
- **`sorting.ts`** — режимы `dateDesc` / `amountDesc` / `amountAsc`. Сортировка
  по сумме приводит валюты к отображаемой, иначе сравнение бессмысленно.
- **`TrStats.tsx`** (430 строк) — панель статистики по текущей выборке:
  сколько операций попало под запрос и на какую сумму.
- **`index.tsx`** — переработан под новый поиск, сортировку и переключение
  между группированным и плоским списком.

## 4. Карточка операции

[`TransactionPreview`](../src/3-widgets/transaction/TransactionPreview/index.tsx):

- Кнопка ✨ **«Создать правило»** — открывает `RuleModal`, засеянный этой
  операцией и её категориями. Показывается только для доходов и расходов.
- Показ **MCC** операции.
- **Внутренний id** операции с копированием в буфер. Суммы повторяются, id —
  нет, поэтому это единственный способ показать на конкретную операцию: копируешь
  и вставляешь в поиск.

## 5. Фильтрация — новые условия и починка вложенности

[`5-entities/transaction/filtering.ts`](../src/5-entities/transaction/filtering.ts):

- Новые условия `payeeText` и `commentText` — поиск подстроки без учёта регистра
  отдельно по месту платежа и по комментарию.
- **Исправлено:** `showDeleted` теперь наследуется во вложенные условия `or`/`and`.
  Раньше вложенное условие проверяло удалённость по умолчанию и молча выбрасывало
  удалённые операции, даже когда родитель просил их показать.

## 6. Настройки и категории

- **`ignoreTransfers`** в [`userSettings`](../src/5-entities/userSettings/userSettings.ts)
  (по умолчанию включено) — прятать переводы между своими счетами в поиске: это
  не траты и они только портят итоги.
- **Предупреждение о дубле названия категории** в
  [`EnvelopeEditDialog`](../src/2-pages/Budgets/EnvelopeEditDialog/EnvelopeEditDialog.tsx).
  Создание конверта создаёт категорию в ZenMoney, и ничто не мешает завести две
  с одинаковым именем — после чего они неразличимы в любом выпадающем списке,
  отличаются только по id. Теперь об этом говорится до того, как это случится.
  Сравнение нормализует регистр и `ё`/`е`.

## 7. Мелочи

## 9. Ребрендинг в Zerno

- **Убрано чужое.** Из [`index.html`](../index.html) вырезаны GTM-контейнер
  автора (`GTM-KPJGK2L`, скрипт и noscript-iframe), `google-site-verification`
  от его Search Console и `twitter:creator`. Из пяти страниц убраны
  `rel="canonical"` на `zerro.app` — они отдавали наши страницы за чужие.
- **Тексты и метатеги** переведены на Zerno, `robots` — `noindex, nofollow`,
  [`robots.txt`](../public/robots.txt) — `Disallow: /`: инстанс личный.
  `og:url` и `og:image` пока не заполнены, ждут домена.
- **Знак.** Зерно, разрезанное диагональю 42° на три доли — глина, янтарь,
  олива: три тона одной светлоты и насыщенности, то есть равноправные
  категории. Прямая отсылка к тому, что приложение делает с одним заказом.
  Плашка `#241D14` вместо синеватого `#00090F`, `theme_color` обновлён.
- **Ассеты** в [`public/icons/`](../public/icons) собраны генератором:
  геометрия долей считается из параметров (угол реза, точки разреза, просвет),
  контур зерна разбивается на полигоны отсечением по полуплоскостям, растр и
  PNG пишутся напрямую через `zlib`. На машине не было ни одного
  растеризатора, поэтому свой. Отдельно `mask-icon.svg` — плоский силуэт для
  закреплённых вкладок Safari, туда цветной знак не годится.
- **Убрано авторское содержимое.** Страница донатов удалена целиком — вместе с
  маршрутом, двумя пунктами навигации, пространством переводов `donation` и
  `.github/FUNDING.yml`, который вешал на репозиторий кнопку Sponsor с патреоном
  и личной карточной ссылкой автора. Три статьи в `About` (шесть MDX на двух
  языках со скриншотом и телеграм-каналами) тоже удалены: маршрут `/about`
  остался, но отдаёт заглушку — свой текст ещё не написан.
- **Экран входа.** Убрана ссылка «Not loading? Try this». Это была не битая
  ссылка, а вход через альтернативный эндпоинт ZenMoney (`logIn('app')` вместо
  `logIn('ru')`, то есть `zenmoney.app` вместо `zenmoney.ru`) — если вход
  однажды перестанет проходить, дело в этом.
- **[`Logo.tsx`](../src/6-shared/ui/Logo.tsx)** больше не рисует буквы ZERRO
  контурами: знак плюс «Zerno» текстом в IBM Plex Sans. Рамка подогнана по
  реальной ширине контента.

## Чего здесь ещё нет

Осознанно отложено, чтобы не мешать в одном коммите:

- **Свой текст для `/about`.** Сейчас там заглушка. Описание метода и быстрый
  старт нужно написать заново — от апстрима не осталось ничего.
- **MDX больше не используется.** После удаления статей в проекте нет ни одного
  `.mdx`, а плагин `@mdx-js/rollup` в [`vite.config.ts`](../vite.config.ts) и
  зависимости `@mdx-js/react` / `@types/mdx` остались. Выкинуть при следующей
  правке зависимостей.
- **Переименование служебного счёта** `🤖 [Zerro Data]`. Решение отложено:
  поиск скрытых данных идёт по полю `type` внутри JSON по всем reminder'ам, а не
  по счёту, поэтому переименование счёта данные не изолирует, зато создаёт второй
  служебный счёт и вытаскивает старый в списки UI.
- **Деплой.** Прод-`Dockerfile` (текущий поднимает dev-сервер), конфиг прокси,
  свой consumer key ZenMoney, ограничение доступа.

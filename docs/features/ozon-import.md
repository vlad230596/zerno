# Импорт заказов Ozon

Статус: **разведка закончена, парсер работает, в приложение не встроен.**
Связано: [composite-operations.md](./composite-operations.md),
[auto-categorization.md](./auto-categorization.md), [split-bill.md](./split-bill.md)

Ozon — первый источник, который закрывает состав покупки. Заказ приходит с товарами,
ценами, ссылками, картинками и категорией, то есть ровно с тем, из чего собирается
[составная операция](./composite-operations.md): вход — списание, выходы — позиции.

## Почему Ozon, а не чеки ФНС

Решение принято осознанно и не зависит от того, заработает ли путь через чеки.

- Ozon даёт ссылку на товар, картинку, описание, продавца и категорию. В фискальном
  чеке ничего этого нет: там только строка названия, зачастую нечитаемая, и её всё
  равно пришлось бы чистить руками перед автокатегоризацией.
- Проверка по факту: поле `qrCode` заполнено у **0 транзакций из 8302**. Механизм,
  на который рассчитывает [receipt.ts](../../src/6-shared/helpers/receipt.ts), в
  реальных данных мёртв — он парсит то, чего нет.
- Вход в «Мои чеки онлайн» (`lkdr.nalog.ru`) требует капчи и СМС, то есть не
  автоматизируется. И чек не равен заказу: отправления бьются по продавцам,
  склейка возможна только эвристикой дата + сумма.

Разбор чеков остаётся отдельной задачей, а не предусловием этой.

### Категория требует отдельного запроса

В самом заказе категории нет ни в каком виде. Она достаётся с карточки товара:
`/product/<SKU>/` (слаг не нужен) отдаёт виджет `breadCrumbs` с полной цепочкой и
ID категории в ссылке (`/category/kuhonnye-instrumenty-19009/` → `19009`).

Покрытие падает с возрастом заказа, потому что снятый с продажи товар отдаёт вместо
карточки страницу поиска (`pageType: "search"`):

| Год | Позиций | С категорией |
|---|---|---|
| 2026 | 107 | 79 % |
| 2025 | 116 | 58 % |
| 2021 и старше | 94 | 0–14 % |

Для текущей работы это приемлемо: категории нужны на новых заказах. Запрос на SKU
кэшируется навсегда — категория товара не меняется.

## Как устроен обход

Кабинет — SPA на виджетах. Страница собирается запросом
`/api/entrypoint-api.bx/page/json/v2?url=<путь>`, ответ — `{layout, widgetStates}`,
где `widgetStates[stateId]` это JSON-строка. Запасной вход — `composer-api.bx`
с тем же путём.

Запрос обязан выполняться **на странице ozon.ru**, с `credentials: 'include'`.
Тогда он неотличим от штатного запроса самого сайта. Из внешнего HTTP-клиента те же
адреса отдают цепочку 307 с `?__rr=` и затем 403 «Antibot Challenge Page» —
антибот у Ozon собственный (`abt-` на `st.ozone.ru`).

### Три ловушки, каждая из которых молча теряет историю

Ни одна не падает с ошибкой — все возвращают часть данных как будто целое.

1. **Пагинаторов два.** Нужен тот, у которого `layoutContainer` начинается на
   `order-list`; второй принадлежит ленте рекомендаций. По неправильному обход
   отдаёт 66 заказов вместо 164.
2. **Продолжение переезжает.** На первой странице `nextPage` лежит в виджете-пагинаторе,
   на всех последующих — в **корне ответа**. Если искать только в `widgetStates`,
   история обрывается ровно на 25 заказах (12 + 13).
3. **Архив по умолчанию отдаёт только свежее.** Полная история — перебором годов из
   виджета `orderFilters` (`?selectedTab=archive&selectedYear=YYYY`). Курсор руками
   не собрать: сервер требует своих `archive_orders_state_change_moment` и
   `start_page_id`, а `layout_page_index` и офсеты игнорирует.

Порядок работы двухфазный: сначала список (номера, даты), потом детали только тех
заказов, которых ещё нет. Заказ после выдачи неизменен, поэтому инкрементальный
прогон останавливается на первом известном номере — номера сквозные и возрастающие.

## Сопоставление с транзакциями

По точной сумме, в окне **±21 день**. Так сходится **79,6 %** заказов.

Окно именно такое, потому что банк списывает при оформлении, а фискальный чек
выбивается при выдаче; между ними бывает больше недели. На ±4 днях сходится только 68 %.

Оставшиеся 20 % — оплаты баллами, сплиты и частичные возвраты. Их связывать вручную,
под это в [составных операциях](./composite-operations.md) уже предусмотрен флаг
«требует внимания».

## Важное: заказы покрывают не все траты на Ozon

Собранные заказы за 2025–2026 дают 386 560 ₽, а операций с payee «Ozon» за тот же
период в данных — 796 штук на 1 322 269 ₽.

Разрыв объясняется не потерей данных парсером, а тем, что **часть покупок оформлена
с другого профиля Ozon**, принадлежащего другому человеку, и оплачена со второго счёта.
Парсер работает с тем аккаунтом, в который вошли, и чужие заказы не видит и видеть
не должен.

Практическое следствие: полнота импорта ограничена одним профилем. Если нужны обе
половины — придётся выгружать из каждого профиля отдельно и сливать на стороне zerno.
Закладываться на «Ozon закроет все непонятные траты» нельзя.

## Куда встраивается

- **Модель.** Заказ — это событие из [composite-operations.md](./composite-operations.md):
  вход — существующее списание, выходы — позиции. Своего типа заводить не нужно.
- **Хранилище.** Новый `HiddenDataType` +
  [`makeMonthlyHiddenStore`](../../src/5-entities/shared/hidden-store/monthlyStoreFactory.ts):
  заказы идут пачками, простой стор упрётся в лимит длины комментария напоминания.
- **Обязательный побочный эффект.** Создание события должно ставить входу исключение
  из правил, иначе автокатегоризация перетрёт теги под событием.
- **Категория Ozon → категория zerno.** Цепочка крошек ложится на движок правил
  ([auto-categorization.md](./auto-categorization.md)) лучше, чем строка чека:
  она стабильна, имеет ID и не зависит от того, как продавец назвал товар.

## Доставка данных

У zerno нет бэкенда — браузер ходит только в ZenMoney API. Сходить в Ozon из
приложения нельзя: CORS. Поэтому парсер живёт на стороне Ozon, а zerno принимает
готовый JSON.

Парсер сделан userscript'ом (Tampermonkey), а не расширением и не на Playwright:
headless детектится по `navigator.webdriver`, требует включённого ПК и не переезжает
на телефон. Скрипт не использует ни API расширений, ни Node — только `fetch` со
страницы, поэтому в Firefox Android работает без единой правки.

Приём в zerno: по образцу `loadBackup` с `<input type=file>`
([Auth/index.tsx](../../src/2-pages/Auth/index.tsx)). На Android дополнительно
годится Web Share Target — в манифесте его пока нет.
